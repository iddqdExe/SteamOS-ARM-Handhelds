# UP-01: сессия Steam, QAM, overlays и Decky

Кандидат разработан в `codex/up-01` от `main` `fa389fb28dc624418e3f3436e20a81c6bb87c88a`.
Область приёмки: **Retroid Pocket 6 / SM8550 / 12 ГБ RAM / microSD**.
Исходники и доставка проверяются отдельно от cold boot, reboot и испытаний игры.
Изменения рабочего дерева модуля питания в основной копии не включены.

Лицензия перенесённых скриптов и focusfix — GPL-2.0; авторы hashtagbasit и FearlessSpiff.

## Доставка

`apply-overlays.sh` использует `install-rp6-session.sh` для сессии/units и проверенного Decky.
Настройки InputPlumber и KONKR не изменяются установщиком сессии.
Контроль состава: `python3 scripts/check-rp6-session.py ROOTFS KERNEL [--home STEAMOS_HOME]`.
Он проверяет ARM64 focusfix, pinned Decky, реальные init/helper в BOOT и matching modules.
Корректный rootfs с прежним BOOT не проходит эту проверку.

Prebuilt importer собирает внешний ramdisk с новым helper.
Для существующего нашего busybox BOOT допустима отдельная перепаковка:

```sh
python3 scripts/repack-rp6-initramfs.py KERNEL KERNEL-UP01 --expected-sha256 FULL_SHA256
```

Скрипт требует контрольную сумму, проверяет boot ID, сохраняет compressed Image, DTBs,
cmdline и адреса, сохраняет прочие файлы ramdisk и пишет только новый файл.
Dummy/embedded initramfs отвергается: для `EMBED_INITRAMFS=1` нужен
`external-and-mods/kernel-sm8550/build.sh --repack-boot`, пересобирающий Image.
Свежий source build и embedded kernel пока не собраны; изменение проверено для внешнего ramdisk.

Локальный образ-кандидат можно получить только в Linux от известного регулярного файла:

```sh
python3 scripts/fetch-decky-loader.py
python3 scripts/prepare-rp6-session-test.py BASE.img UP01.img \
  --expected-sha256 FULL_BASE_SHA256 --update-package UP01.tar.gz
```

Это производный тестовый образ, а не чистая сборка всего дистрибутива.
Пакет нужно собирать в Linux filesystem с xattrs и разным регистром имён;
в Docker на macOS используйте native volume для package output, затем копируйте готовый tar.gz.
Пакет ограничен моделью `Retroid Pocket 6`; BOOT и rootfs проверяются как комплект.
При первом обновлении со старым updater нужно до staging доставить текущий проверенный
`konkr-update.py`: конфигурационный установщик ввода уже выполняет этот bootstrap;
установщик сессии также включает новый engine. Старый engine не переносит loader из пакета UP-01.
Факт применения файлов не равен успешной новой загрузке.

## Проверки и открытая приёмка

- ARM64 Linux: 102 теста вместе с opt-in devtools и standby, без пропусков; реальные сценарии Xvfb проверяют восстановление игры,
  исключение Steam и ограничение частоты. Проверены upgrade/rollback loader, пользовательские maps/settings,
  malformed/missing cache, отсутствующий env, повторный вход, SHA/boot ID и отказ embedded repack.
  Реальный security.capability проходит tar extraction → upgrade → rollback.
- Реальный overlay mount в отдельном Linux mount namespace: enabled test unit появляется до systemd,
  повторный вызов не перемонтирует `/etc`, upper сохраняется после unmount.
- macOS: 102 теста, 9 Linux/Xvfb/root сценариев пропущены; это не заменяет Linux прогон.
- Проверены shell syntax и отсутствие whitespace ошибок. Workflow `rp6-session.yml` добавлен;
  удалённый GitHub Actions запуск не выполнялся.
- На RP6 supported update и сохранение enabled `sshd.service` после update проверены.
  Аппаратный rollback, Game Mode и KONKR Control после него проверены;
  контрольный standby после rollback прошёл. Свежий образ загрузился, оконная DMC
  прошла циклы меню и три пробуждения. После смены сессии оверлей восстановился,
  после перезагрузки прошли Game Mode, KONKR Control, автоматический SSH/отчёт
  и standby без игры. Открыты fullscreen QAM в других играх, cold/offline boot
  свежей установки, чистая/embedded сборка и удалённый CI.
  L4/R4, триггеры и обе кнопки громкости повторно проверены пользователем
  на свежей установке.

UP-01 пока **кандидат для аппаратной проверки**; общая аппаратная приёмка остаётся открытой.
Decky prerelease остаётся явно закреплённым тестовым компонентом.

Первая загрузка кандидата на RP6 остановилась на `ETC OVERLAY FAILED` до systemd.
Проверка фактического импортированного ядра выявила `CONFIG_OVERLAY_FS=m`, хотя
фрагмент нашей новой source-сборки задаёт `y`. В минимальном initramfs отсутствует
`/sbin/modprobe`, поэтому автоматическая загрузка модуля до `switch_root` не работает.
Helper теперь при отсутствии OverlayFS в `/proc/filesystems` вызывает `modprobe`
через `chroot` в смонтированный rootfs с соответствующими модулями ядра.
`early-etc.log` сохраняет диагностику; недоступный лог не блокирует корректный mount.
Проверены регрессии модульного/builtin OverlayFS, отказ загрузчика и недоступный лог,
реальный BusyBox из BOOT и dry-run kmod в rootfs образа без `/proc` и `/sys`.
После замены BOOT RP6 загрузился в Game Mode. По SSH подтверждены модель RP6,
ядро `7.0.14-edge-sm8550`, загруженный OverlayFS и смонтированный `/etc` overlay;
системных units в состоянии failed нет. SHA256 Decky совпадает с закреплённым asset,
его backend и KONKR Control запущены. Переход Game Mode → Desktop → Game Mode
выполнен для подключения диагностики. Исправленный BOOT включён в согласованные
`steamos-rp6-up01-fixed-20261002.img` и `rp6-up01-fixed-20261002.tar.gz`.
Доставка и input preflight пройдены; проверены все 192633 payload SHA256 и
10 записей `security.capability`. Исходные файлы с `test` в имени заменены
исправленной парой. Это производный образ, полная сборка дистрибутива из исходников не выполнялась.

В DMC (`220440`, DX9) проверен один цикл правого QAM в полноэкранном режиме:
при открытии меню Wine переводит игру `Normal → Iconic`, хотя X11 geometry
остаётся `1280×720` и `STEAM_SCREEN_SCALE` не меняется. При закрытии UP-01
восстанавливает `Normal` и фокус; пользователь подтвердил возврат размера
и управления без кнопки Resume. Маленькое изображение при открытом меню
остаётся воспроизводимым ограничением. Контрольный тест пользователя в оконном
режиме DMC устраняет этот симптом. Пользователь проверил по пять циклов обоих
меню: размер, управление в игре и в меню сохранились. Последний live snapshot
подтверждает открытый QAM (`STEAM_OVERLAY=1`, X focus у Steam) при `WM_STATE=Normal`
у DMC; игры в других режимах и другие тайтлы этим тестом не приняты.
Сохранение performance overlay проверено в текущем образе: после выбора уровня 2
явный переход в Desktop останавливает gamescope/focusfix, а возврат запускает
новые процессы. Файл `/run/user/1000/mangohud-config` сохраняет inode и `preset=2`;
env атомарно публикуется заново с тем же путём. Пользователь подтвердил автоматическое
отображение уровня 2 в DMC. После перезагрузки пользователь подтвердил Game Mode
и KONKR Control без ошибок; новый boot ID, `/etc` overlay и активные сервисы
подтверждены по SSH. Диагностический SSH сначала был запущен вручную, затем
его enabled-ссылка проверена в постоянном upper `/etc`. После установки opt-in
devtools два удалённых тёплых перезапуска подтвердили автоматический старт SSH,
сохранение узкой sudo-политики и чтение ожидаемого BOOT SHA256. Пользователь затем
полностью выключил и включил RP6 без Wi-Fi и подтвердил Game Mode и KONKR Control
без ошибок. Автоматический отчёт нового boot ID на uptime 54,91 с показывает
Wi-Fi `disabled`, активный SSH, единственный Loader, focusfix и ожидаемый BOOT SHA256.
После включения сети по SSH подтверждены тот же boot ID и Loader PID, активные
службы и отсутствие failed units. Инструменты описаны в
[RP6-DEVTOOLS.ru.md](RP6-DEVTOOLS.ru.md).
После включения Wi-Fi пользователь также подтвердил KONKR Control, управление
в оконной DMC, триггеры, L4/R4, звук и обе кнопки громкости. Проверка сна выявила
отказ: после короткого нажатия питания, ожидания и повторного нажатия физический
экран остался чёрным при работающем звуке; QAM тоже не виден. Фактический путь —
программный `konkr-standby`, а не kernel suspend. Служба завершилась с кодом 0,
процессы и cgroups разморожены, DRM сообщает `On`, снимок gamescope содержит DMC.
Эти системные признаки не подтверждают восстановление физического экрана.
Повторная команда включения панели и отдельный цикл DPMS off/on изображение
не вернули; перезагрузка восстановила Game Mode. Без запущенной игры первый
цикл standby тоже не восстановил экран, а повторный полный цикл восстановил.
Отдельная проверка выявила ошибку порядка восстановления: после обнуления
яркости и DPMS off/on немедленная запись DSI-яркости вернула `Protocol error`,
хотя sysfs уже показывал сохранённое значение. Снимок конечного буфера gamescope
содержал обычный Game Mode при чёрном физическом экране. Повторная запись после
`bl_power=0` вернула изображение. Три контрольных цикла с ожиданием готовности
панели прошли без ошибок записи; пользователь подтвердил изображение и управление.

Исправление `konkr-standby` для RP6 ожидает включения DSI-панели до 3 секунд
перед восстановлением яркости. Ошибка записи или тайм-аут дают код отказа,
при этом остальные устройства и управление всё равно восстанавливаются.
Ожидание не применяется к отдельной PWM-подсветке, которая в исправном Game Mode
также имеет `bl_power=4`, и к другим моделям. Четыре регрессионных теста и проверки
доставки входят в полный набор из 102 тестов: ARM64 Linux без пропусков,
macOS — 9 пропусков. Установщик сессии переносит актуальный исполняемый скрипт,
а preflight отклоняет отсутствующую, устаревшую и неисполняемую копию.
После установки на RP6 прошли пять полных циклов с первого пробуждения:
один без игры, три с оконной DMC и один без игры после перезагрузки. Журнал
подтвердил паузу 0/14 игровых процессов, ожидание панели 0,36–0,41 с и успешное
завершение службы. Пользователь подтвердил экран и управление, а в DMC также звук.
Измеренные периоды ожидания кнопки питания составили примерно 5–96 с;
запрошенные 30 с не считаются точной измеренной длительностью каждого цикла.
После перезагрузки контрольная сумма скрипта и права сохранились, автоматический
SSH и отчёт devtools прошли системные проверки. Эти результаты принимают
программный standby на текущей RP6, а не kernel suspend или другие игры.
Исходный комплект `fixed-20261002` исправления не содержит. Новый образ
`standby-20261003` собран и проверен: 192633 payload SHA256 и 10 capabilities.
Пакет `a4a209b71173fde38d224e0537a75b164b5b010f59c0c51d24607441c60b70c5`
реально установлен через SSH и штатный initramfs recovery на RP6. Транзакция
`6f6d4f9e-eaaa-4116-ba89-5f98ff1132a4` завершилась `committed`, без pending marker
и ошибок; новый boot ID получен примерно через 19 минут. До запуска systemd экран
был чёрным, а журнал обновления сохранялся в HOME. BOOT, standby и Decky совпали
с ожидаемыми SHA256, все 10 live capabilities сохранены. Первый автоматический
отчёт подтверждает активные SSH/Decky/focusfix и единственный Loader; root coverage
ограничена, поскольку стандартный пакет заменил отдельно установленный helper
в `/usr`. Проверенные opt-in devtools восстановлены, полный live отчёт проходит
системные проверки; preset 2, манифест DMC и настройки Decky сохранились.
При повторной установке devtools выявлены исходные права штатных sudoers-файлов:

Это отдельная настройка устройства; сохранённый комплект восстановления не изменён.
Полная сверка backup с исходной описью прошла для всех 236312 постоянных объектов

Шесть живых GnuPG IPC sockets записаны отдельно и не включены в постоянную опись.
Пользователь подтвердил Game Mode и KONKR Control после пакета, затем экран
и управление после одного полного standby без игры. Журнал фактической службы

Первоначальный запрос журнала к несуществующей `konkr-standby.service` был ошибкой

Комплект отката повторно полностью сверён; опубликован `rollback-requested`

права, ссылки и xattrs; различий нет, SHA256 описи `d8a154a2c8418673c139907e9b7dcbed6ac42ecae3b6a82809ac8209dbe7a6a4`.
Контрольный файл `homebrew/services`, удалённый при apply, вернулся с исходным
SHA256. Версия Decky до и после одинакова; проверено восстановление каталога loader,

Манифест DMC, настройки Decky и preset 2 сохранились; SSH включился автоматически.
Пользователь подтвердил Game Mode и KONKR Control без ошибок.

к `0440` как отдельная настройка разработки; глобальный `visudo` прошёл,

Контрольный standby без игры после rollback прошёл с первого пробуждения:
пользователь подтвердил изображение и управление, журнал — один полный цикл

Завершение службы успешно, SSH вернулся автоматически в той же загрузке;

Свежая установка образа, общая приёмка UP-01 и проверки других игр продолжаются.

## Откат

До установки сохранить полный backup принятой microSD и отдельный комплект BOOT/rootfs/HOME loader.
Сверить модель, носитель и SHA256; игры хранить как `steamapps` + `appmanifest_*.acf`,
сохранения и конфигурацию — отдельно. В производном кандидате остаётся `KERNEL-before-UP-01`;
он не заменяет полный backup и не является автоматическим boot fallback.

Обновлятор сохраняет согласованные старые `/usr`, `/opt`, `/etc`, persistent upper,
плагины, `homebrew/services` и BOOT. Проверен откат файлов в временных Linux roots
и на текущей RP6: весь управляемый постоянный состав совпал с исходной описью.
Если boot не дошёл до recovery, возвращать принятую карту/образ с компьютера.
Ручной возврат одного KERNEL нельзя считать откатом всей сессии/Decky.
