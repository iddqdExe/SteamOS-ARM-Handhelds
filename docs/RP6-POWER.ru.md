# Питание RP6

Текущий перенос UP-04 описан в [RP6-UP-04.ru.md](RP6-UP-04.ru.md). База — принятый UP-03 Linux 7.2.8 и его R2 userspace. UP-04 принят 2026-10-05 в согласованном объёме RP6/12 ГБ/microSD и выбран пользователем основой `main`. Основной режим — standby; s2idle включается явно.

Принятые частоты/CPU profiles/GPU range, standby-aware fan и thermal failsafe наследуются из R2 image. Daemon не заменяется целиком исходниками другой ветки; в принятую версию внесена точечная защита кнопки пробуждения. При переносе recovery guards старого модуля 2 сохранено более позднее исправление UP-03: ждать готовности DSI панели перед возвратом яркости. Старое PWM-only правило кандидата module2 для иной панели не заменяет принятую реализацию 7.2.8.

`scripts/install-rp6-power.sh` доставляет согласованные standby, sleep, suspend, state/recovery, CLI и systemd units в офлайн ROOT. Образ и update package UP-04 используют тот же точный набор. Частичная подготовка отменяется с восстановлением; сбой восстановления отражается в журнале и оставляет запись для повторной попытки. Предыдущие настройки Wi-Fi/wakeup/touch сохраняются только на время перехода в оперативном `/run`, это не backup устройства или данных карты.

Историческая база модуля 2 — `rp6/module2-power`, SHA `a8aee376df256957cdc078e482479d6750e2d9f0`; весь модуль питания тогда не был принят из-за перемежающегося отказа звука и расхода при длительном standby. Эти наблюдения не считаются исправленными одними source tests UP-04. По решению пользователя выполнены пять коротких циклов, включая зарядку, отдельный сон 767 секунд и повторная проверка DuckTales после исправления кнопки пробуждения. Последующая загрузка с автоматическим SSH подтверждена. Ночной расход и расширенная матрица остаются неизмеренными; новые source tests их не заменяют.

Приоритет: стабильность → производительность → автономность. Измерения и результаты для RP6 / SM8550 / 12 ГБ / microSD отделяются от исходников, доставки и CI. Активный USB-PD reset пока не включён без подтверждённого RP6 дефекта.
