# RP6: тестовая SteamOS на USB SSD

**Статус, 1 октября 2026:** USB-загрузка не подтверждена. Пользователь остановил
этот вариант и разрешил чистую установку обычного SD-кандидата модуля 1 на
microSD без backup. Документ ниже сохраняет историю SSD-эксперимента.
После перезаписи карты прежняя microSD больше не является физическим откатом.

Решение пользователя от 1 октября 2026: остановить полное копирование рабочей
microSD, оставить её носителем для отката и использовать отдельный SSD 2 ТБ
для разработки. На SSD нет данных, которые пользователь просил сохранить.
microSD не перезаписана, KERNEL проверен по прежнему SHA256, карта штатно
извлечена. Проверенного полного файлового backup карты нет; незавершённый
образ удалён после остановки процессов.

Это экспериментальный вариант кандидата модуля 1 на базе исправленной beta8,
не выпуск 1.0 и не завершённая аппаратная приёмка. Все изменения ядра и DTB
для кнопок сохранены. Для SSD заменён ранний загрузочный архив: поиск root
по уникальному UUID только среди USB-разделов, ранние USB/ADSP модули с
зависимостями и прошивки ADSP/CDSP по путям из DTB. Исходный SD initramfs
искал microSD, поэтому простой перенос SD-образа не обеспечивает USB-загрузку.
Все три файловые системы SSD получили независимые UUID; карта не используется
как загрузчик и не выбирается при отсутствии SSD.

## Разметка и подготовка

Целевой накопитель: внешний USB `GEND 900`, 2 048 408 248 320 байт,
в кейсе Ugreen/RTL9210. Номер устройства Mac проверяется непосредственно
перед записью; старый номер не используется без проверки модели и размера.

- BOOT: 512 МиБ, FAT, метка `RP6SSD`.
- root: около 11,4 ГиБ, ext4.
- HOME: раздел 128 ГиБ; исходная файловая система увеличивается при первой
  загрузке через `x-systemd.growfs`. Штатная служба растягивания раздела на весь
  диск отключена. Остальное пространство остаётся неразмеченным.

На Mac хранятся материалы вне Git: `../preparation/ssd-test/`.
`rp6-module1-ssd-prefix.img` — установочный префикс 16 447 963 136 байт,
не полный образ SSD. Его нельзя использовать как полный backup и нельзя
записывать на рабочую microSD. Разметка HOME выходит за границу файла;
установщик проверяет, что реальный SSD вмещает весь раздел.

Подготовка проверяет исходный SHA256, неизменность kernel payload, заголовок
KERNEL, профили ввода, запуск ARM64 InputPlumber и чистоту BOOT/root/HOME.
Отдельные тесты проверяют запрет записи на SD и внутренний диск, границы
копирования, короткое чтение, несовпадение записи, отказ выбирать microSD,
внутренний SCSI-диск и неоднозначный USB UUID. Поиск разделов также проверяется
ARM BusyBox из реального initramfs. Установщик перед записью проверяет
SHA256 префикса, модель/размер/USB, исходный UUID SSD и размонтирование.
После записи он читает каждый байт префикса обратно, сравнивает с источником
и проверяет SHA256. Прежняя резервная GPT в последних 34 секторах удаляется
отдельной ограниченной записью и также проверяется.

Состояние физической установки хранится в
`../preparation/ssd-test/installation-status.json`. Только `phase: verified`
и `verified: true` подтверждают запись и проверку SSD. USB-загрузка этим не
подтверждается. Текущий кабель на Mac согласовал USB 2.0, 480 Мбит/с;
для ускорения последующих итераций нужен кабель передачи данных USB 3.x.

1 октября 2026 запись на проверенный GEND 900 выполнена. Все
16 447 963 136 байт прочитаны обратно и совпали с источником. SHA256 префикса:
`8170a6a70146959f50dd39d4f77e637b28b187e12059a2b822ddb5f386fed137`.
Очистка резервной GPT проверена; запись и чтение заняли 924 секунды,
SSD штатно извлечён. Аппаратная загрузка на RP6 пока не проверена.

После первой аппаратной попытки ABL сообщил `No bootable image found`;
на повторной попытке в режиме Verbose ошибка исчезла, но экран оставался
чёрным. Возвращённый SSD проверен с BOOT, смонтированным только для чтения:
KERNEL сохранил исходный SHA256, `ssd-bootlog.txt` отсутствует. Это означает,
что журнал после обнаружения USB root не был записан; точный этап остановки
пока не установлен.

Для следующей попытки установлен **диагностический KERNEL** с выводом на экран.
Изменён только заголовок с командной строкой; kernel payload, DTB, initramfs,
root UUID и способ выбора USB-раздела сохранены. Убраны quiet, loglevel=0
и video=efifb:off; включены tty0, ранняя EFI-консоль, сообщения ядра и systemd.
SHA256 первого диагностического KERNEL:
`88f9709e58fe55b60441df4b34dfac146662086ab539e6f878fd9d18f11064b8`.
Прежний файл сохранён на SSD как `KERNEL-before-usb-console` и на Mac в
`../preparation/ssd-test/boot-returned-20261001/KERNEL`. После повторного
монтирования BOOT только для чтения оба файла и KERNEL.md5 проверены.
Приведённый выше SHA256 установочного префикса относится к первоначальной
записи, до этой правки командной строки. Диагностический вывод — сбор
доказательств, а не подтверждённое исправление USB-загрузки.

В двух попытках с выводом на экран Linux сообщил об отказе монтирования SSD.
Это подтверждает выполнение initramfs, но точный текст ошибки не сохранён.
Фраза `Working microSD has not been used` означает, что рабочая карта **не
использована**; перехода на microSD в этом загрузчике нет. На возвращённом
SSD BOOT снова не содержал журнала. Прямое чтение ext4 superblock подтвердило
ожидаемые UUID root и HOME и чистое состояние обеих файловых систем.

Установлен второй диагностический KERNEL. Он показывает блок
`=== RP6 USB ROOT DIAGNOSTICS ===`: обнаруженные диски и UUID, USB-устройства,
USB role, состояние remoteproc и последние сообщения USB/firmware. Поиск
BOOT и сохранение `ssd-usb-snapshot.txt` теперь выполняются независимо от
успеха поиска root. Сохранение требует обнаружения BOOT именно на USB SSD
с заданным UUID. Из initramfs изменён только `init`, добавлен
`usb-snapshot.sh`; kernel payload, DTB, cmdline, selector, модули и firmware
сохранены. Архив прочитан независимым CPIO reader; ARM BusyBox проверил shell
syntax, 12 проверок безопасности и выбора USB-раздела прошли.

SHA256 второго диагностического KERNEL:
`30037b3062c3f15c8d447877b0562d65d94c1983fd6e1b3e9dc5f9b3dbb3d111`.
Первый диагностический файл сохранён на SSD как `KERNEL-before-usb-snapshot`.
Это дополнительный сбор данных; работоспособность USB-загрузки ещё не
подтверждена. При остановке нужно сохранить фотографию диагностического
блока или точный текст последних сообщений.

В следующей попытке повторяющиеся предупреждения RSInput могли вытеснить
диагностику с экрана. Возвращённый BOOT сохранил правильный KERNEL, но оба
журнала отсутствуют. `RX buffer overflow` относится к UART контроллера;
`MCU parameters set successfully` подтверждает ответ его MCU, а не USB root.

Для читаемости установлен KERNEL-usb-screen с `loglevel=4` без
`ignore_loglevel`: ошибки ядра и экран init сохраняются, повторяющиеся
предупреждения RSInput не печатаются. Все байты после 2048-байтного header,
включая kernel, DTB и initramfs, неизменны относительно второго кандидата.
Текущий KERNEL SHA256:
`cf1ccd3eb75edfb38cb30c4a3bad46a65873f52d706cfd9845e7b41486b48b2f`.
Прежний файл сохранён как `KERNEL-before-usb-screen`.
Это диагностическая итерация; причина отказа USB-загрузки ещё не установлена.

## Первая загрузка

После подтверждённой записи и штатного извлечения SSD:

1. Полностью выключить RP6. Оставить рабочую microSD отдельно и подключить SSD
   к USB-C RP6 до включения.
2. Включить RP6 с удержанием Volume−, чтобы открыть существующее меню ABL.
   Выбрать Linux и USB как источник загрузки, сохранив модель Retroid Pocket 6.
   Если меню использует отдельный пункт `Switch boot mode`, источник выбирается
   через него. Новую прошивку ABL не устанавливать.
3. Дождаться первой загрузки. Проверить, что HOME увеличился до 128 ГиБ,
   root/BOOT/HOME относятся к SSD и присутствует
   `/opt/steamos-sm8650/SSD-TEST.json`.
4. Подключить SteamOS к Wi-Fi. Пройти [проверку модуля 1](RP6-INPUT.ru.md#аппаратная-приёмка-и-откат):
   крестовина, ABXY, оба меню, независимые L4/R4, остальные органы управления,
   холодная загрузка, Game/Desktop Mode и отсутствие дублей контроллера.

ROCKNIX ABL заявляет [USB-загрузку](https://github.com/ROCKNIX/abl).
Вход Volume− описан в [инструкции RP6](https://rocknix.org/devices/retroid/retroid-pocket-6/).
Работа этого SSD, кейса и ядра в USB-загрузке пока не подтверждена на RP6.

Если USB отсутствует в меню или загрузка зависает, сохранить текст ошибки
и состояние индикатора кейса. Не менять рабочую карту для обхода ошибки.
Если ядро нашло SSD, ранний журнал появляется в `RP6SSD/ssd-bootlog.txt`,
доступном на Mac после подключения. Если ABL не смог прочитать KERNEL,
этого журнала не будет. В экспериментальном initramfs нет обработки
`konkr-update/pending`; полное обновление ОС на SSD пока не проверено.

## Откат и границы испытаний

Полностью выключить RP6, отключить SSD, вставить исходную microSD и выбрать
Linux/SD Card в существующем ABL. Вернётся прежняя рабочая beta8 с играми.
Для такого возврата копировать данные с компьютера не требуется.

Запись SSD и возврат microSD не затрагивают Android или ABL. Настройки и игры,
созданные на SSD, при возврате microSD сами не переносятся. Экспериментальные
изменения SSD требуют собственного способа отката: копий изменяемых файлов,
KERNEL или BOOT/root по области изменения. Исходный установочный префикс
не сохраняет новые данные HOME.

Результаты ввода полезны для модуля 1, но итоговый выпуск нужно проверить
на целевой microSD. Сон, питание и производительность с внешним SSD могут
отличаться; их окончательная приёмка также повторяется без SSD. Процедура
полного backup и восстановления единственной microSD остаётся обязательной
перед её будущей перезаписью и для соответствующих сценариев модуля 4.
