# RP6: управление в новом образе SteamOS

Цель форка и аппаратной приёмки: **Retroid Pocket 6, Snapdragon 8 Gen 2 / SM8550, 12 ГБ ОЗУ**, с установкой и загрузкой SteamOS с **microSD**. Проверки исходников на компьютерах и CI не заменяют испытания на этой конфигурации. Другие устройства и объёмы памяти не входят в область аппаратной проверки форка.

Статус на 2 октября 2026: исправления включены в пути установки конфигурации,
импорта prebuilt ядра и проверки перед упаковкой SM8550 образа. Закрыты
проверка ARM64-зависимостей и сохранение пользовательских назначений при
установке, обновлении и откате. Подготовка тестового образа описана ниже.
Модуль 1 принят 2 октября 2026 для установленной конфигурации RP6 12 ГБ
с microSD: основные кнопки, плавный ход LT/RT, независимые игровые назначения
задних кнопок и сохранение управления после сна, полного выключения
и смены режимов подтверждены пользователем.

Пользователь подтвердил, что после предыдущих ручных фиксов управление на
установленной beta8 работает. Цель этого изменения — воспроизводить те же
исправления при сборке, без ручного ремонта после установки.

## Что доставляет сборка

| Физическое управление | Событие Linux | Цель InputPlumber |
| --- | --- | --- |
| Крестовина | BTN_DPAD_UP / DOWN / LEFT / RIGHT | DPadUp / Down / Left / Right |
| Кнопка левого меню | BTN_MODE | Guide |
| Кнопка правого меню | BTN_BACK | QuickAccess |
| Левая задняя кнопка | GPIO57 → BTN_Z | LeftPaddle1 |
| Правая задняя кнопка | GPIO58 → BTN_C | RightPaddle1 |

Назначения ABXY, стиков, плечевых кнопок, триггеров и Start/Select сохранены.
`retroid_mcu.yaml` побайтно совпадает с картой из прежнего локального фикса
`../preparation/rp6-input-fix/retroid_mcu.yaml`; перестановка ABXY заново не вводилась.
Основные действия в Steam и независимые игровые назначения задних кнопок
подтверждены на установленном SD-кандидате с исправлением триггеров.

`scripts/install-inputplumber-sm8550.sh` теперь устанавливает профиль
`02-retroid-pocket.yaml` и карту в `/etc/inputplumber` и
`/usr/share/inputplumber/capability_maps`. Если rootfs содержит постоянный
слой `/var/lib/overlays/etc/upper`, заводские профиль и карта обновляются также там.
Это работает при обычной сборке и при `--image-only`, которая пропускает
`apply-overlays.sh`, но вызывает установку InputPlumber через `prepare_runtime`.

Профиль выбирается по модели RP6 и захватывает только
`rsinput-gamepad/input0` и `gpio-keys/input0`. Внешние USB/BT контроллеры и
виртуальный `deck-uhid` не входят в его список источников. Пользователь дал
общее подтверждение работы запрошенных проверок, включая совместную работу
с внешним геймпадом; модель и способ подключения отдельно не зафиксированы.

`scripts/import-sm8550-kernel.sh` вызывает `fix-rp6-paddles.py` перед упаковкой
загрузочного файла. Скрипт добавляет отсутствующие определения задних кнопок
в RP6 DTB через `fdtput`, сохраняет все исходные свойства кроме дополнения
`/gpio-keys/pinctrl-0`, не перекомпилирует DTS и не меняет сжатое ядро или
DTB других моделей. Корректные определения повторно не меняются;
частичные или конфликтующие определения останавливают импорт.

Распиновка перенесена из [ROCKNIX RP6 DTS](https://github.com/ROCKNIX/distribution/blob/a55d58a1209b35e287dd55a3aad67a5543b467ce/projects/ROCKNIX/devices/SM8550/linux/dts/qcom/qcs8550-retroidpocket-rp6.dts).
Для kernel source build эти описания уже должны приходить из ROCKNIX.
Перед упаковкой SM8550 образа проверяется выбранный основной `KERNEL`,
поэтому повторное использование старого prebuilt output не обходит проверку.
При ошибке образ не создаётся и существующий файл образа не очищается.

## Сборка и проверка

Полный образ собирается в ARM64 Linux среде на Linux файловой системе,
как описано в [building.md](building.md). Python-скрипт использует только
стандартную библиотеку; для изменения DTB нужны `dtc` и `fdtput`
(пакет `device-tree-compiler` в Debian/Ubuntu).

Для старого prebuilt ядра повторить импорт исходного образа. Импорт заменяет
папку output с той же версией: сначала сохранить её отдельную копию.

```sh
sudo scripts/import-sm8550-kernel.sh /work/source-sm8550.img /work/kernel-prebuilt
sudo env SOC=sm8550 ./make-steamos-sm8650.sh
```

Сборка сама проверяет профиль/карты RP6 и GPIO-определения в основном ядре
перед созданием разделов образа. Проверку можно запустить отдельно:

```sh
scripts/check-rp6-input.sh /work/rootfs /work/kernel-prebuilt/7.0.14-edge-sm8550/boot/KERNEL
```

Для обновления только конфигурации в **подготовленном rootfs**, без скачивания
или замены InputPlumber, доступен режим:

```sh
scripts/install-inputplumber-sm8550.sh /work/rootfs --config-only
```

Эти команды предназначены для сборки или подключённого офлайн rootfs.
На работающую RP6 отдельно доставлены исправление диапазона триггеров
и порядок его применения перед запуском InputPlumber; результат приведён ниже.

## Сохранение назначений и откат конфигурации

`rp6-input-config.py` управляет двумя файлами RP6 в `/etc/inputplumber`
и соответствующими файлами persistent upper. При первой установке создаются
отсутствующие файлы. Существующие файлы обновляются, если совпадают с новым
заводским вариантом либо с последним установленным вариантом, SHA256 которого
записан в `/var/lib/rp6-input/managed.json`. Неизвестные и изменённые файлы
сохраняются активными. Если пользователь изменил нижний `/etc`, отсутствующий
верхний файл не создаётся поверх него. Новые заводские варианты отдельно
доступны в `/usr/share/rp6-input/defaults`.

Остальные существующие карты и профили в `/etc/inputplumber`, включая
пользовательские профили мыши, установщик сохраняет. `/usr/share` содержит
заводские ресурсы; свои настройки следует хранить в `/etc/inputplumber`.
Steam Input и данные Steam в HOME не входят в область изменения.

Последнее изменение файлов сохраняется в закрытом для обычного пользователя
`/var/lib/rp6-input/last-update.json`. Повторная установка без изменения файлов
не стирает полезную резервную копию. Откат конфигурации офлайн:

```sh
sudo python3 /work/rootfs/usr/lib/steamos/rp6-input-config.py /work/rootfs --rollback
```

Если после установки пользователь изменил файл, откат откажется перезаписывать
его. Этот откат касается конфигурации ввода; обновлятор и ядро возвращаются
из полной резервной копии системы.

Обновлятор сохраняет весь `/etc/inputplumber` в нижнем и верхнем слоях, затем
обновляет только управляемые заводские файлы RP6. Его общий откат возвращает
также журнал `/var/lib/rp6-input`. Это проверено на временных Linux rootfs
с настоящим копированием файлов при обновлении и восстановлении.

**Первая доставка на старую beta8:** прежний обновлятор копирует себя в среду
восстановления и сам не знает о сохранении InputPlumber. Одного нового
обновлятора внутри пакета недостаточно. Рекомендуемый сейчас путь — новый
тестовый образ на отдельном носителе либо чистая переустановка на microSD.
1 октября пользователь отказался от SSD и явно разрешил перезапись единственной
microSD без backup, с удалением прежней ОС и игр. Для этой установки используется
обычный SD-кандидат ниже, а не экспериментальный USB-образ.
При обслуживании
существующего офлайн rootfs `--config-only` также устанавливает новую версию
`/usr/share/konkr-update/konkr-update.py`; сделать это нужно до подготовки
первого обновления. Пакетное обновление старым обновлятором без этой подготовки
не входит в проверенный путь модуля 1. Аппаратная проверка полного пакетного
обновления и восстановления остаётся обязательной для этого способа доставки
в рамках модуля 4. Приёмка управления на чисто установленной microSD
с исправлением триггеров не подтверждает такую транзакцию обновления.

## Аппаратная приёмка и откат

У пользователя одна microSD и отдельный USB SSD 2 ТБ. После неудачных попыток
USB-загрузки пользователь 1 октября явно отменил этот вариант и разрешил
чистую установку кандидата модуля 1 на microSD **без backup**. Предыдущая ОС,
игры, настройки и сохранения на карте при этой установке не сохраняются.
SSD-эксперимент оставлен в [отдельном журнале](RP6-SSD-TEST.ru.md), его
USB-загрузка не подтверждена. Проверенной полной копии старой карты нет.

Для чистой установки заново определить физическую SD-карту по типу интерфейса,
модели, размеру и прежним UUID root/HOME; номер диска из предыдущей операции
не считать подтверждением. Проверить SHA256 обычного SD-кандидата, размонтировать
карту, записать полный установочный образ и прочитать все записанные байты
обратно. Это создаёт новую разметку и файловые системы; отдельное форматирование
перед записью не нужно. Локальный установщик и статус находятся в
`../preparation/module1/write-test-card.py` и `card-installation-status.json`.
Только `verified: true` подтверждает завершённую проверку записи. Первый запуск
должен увеличить HOME до свободного пространства карты; этот результат
проверяется на RP6. Выбрать Linux / SD Card в существующем ABL.

1 октября чистая запись на проверенную microSD 512 711 720 960 байт выполнена
без backup. Все 16 447 963 136 байт прочитаны обратно и побайтно совпали
с SD-кандидатом; SHA256 совпал с `77b6f6a6ea6e87b4292c890672dc2f64d8ca1eef1f452567c46bf2ccce405e80`.
Запись и проверка заняли 508 секунд, карта штатно извлечена. Установлены
beta8 userspace, исправленный KERNEL и заводская конфигурация модуля 1.
Пользователь подтвердил первый запуск SteamOS с этой microSD. 2 октября
подтверждено сохранение управления после сна, полного выключения/включения
и перехода Game Mode → Desktop Mode → Game Mode. В последнем прогоне
подтверждены независимые игровые назначения L4/R4.

В диагностике через SSH подтверждены RP6, ядро `7.0.14-edge-sm8550` и
активный InputPlumber `0.81.0` с профилем Retroid Pocket и целью `deck-uhid`.
SHA256 установленного заводского профиля и обеих копий карты возможностей
совпали с исходниками сборки. HOME расширен: раздел `mmcblk0p3` — 465,6 ГиБ,
файловая система ext4 — около 458,4 ГиБ, свободно около 455 ГиБ.
При начальной SSH-диагностике ошибок в журнале службы InputPlumber не было; это не подтверждает
аналоговый диапазон триггеров или восстановление после сна.

В первом пользовательском прогоне ABXY, крестовина и остальные кнопки
работают; оба меню открываются, задние кнопки работают, одно нажатие даёт
одно действие. Пользователь сообщил, что триггеры показывают только 0 и
полное нажатие и подтвердил скачок 0→100% при медленном нажатии обоих LT/RT.
45-секундный замер установил причину: сырые ABS_Z/ABS_RZ имеют диапазон
−32768…32767 и 321/359 различных значений, но объявляют диапазон 0…1830.
InputPlumber нормализует по объявленному диапазону и обрезает почти весь ход:
виртуальный HID получил только 11 различных значений каждого триггера.
В заводском профиле они уже объявлены аналоговыми (`value_type: trigger`).

В исходниках `sm8550-fixpad` добавлена коррекция описания обеих осей до
−32768…32767 для проверенных RP6 и `7.0.14-edge-sm8550`. Выбирается точный
физический путь `rsinput-gamepad/input0`; другие модели и версии ядра не
получают эту коррекцию. Перед каждым запуском InputPlumber калибровка
повторяется через `ExecStartPre`; если родной контроллер ещё не появился,
служба повторяет попытку запуска, чтобы не сохранить старые метаданные.
Установщик, preflight, CI и манифест SD-кандидата включают исправление.
Все 37 регрессионных тестов прошли в Linux без пропусков.

Исправление установлено на работающую RP6; SHA256 обоих файлов совпали
с подготовленным helper и drop-in. В повторном 45-секундном замере виртуальный
контроллер передал 422 различных значения LT и 354 RT, включая оба конца
диапазона и промежуточные значения в каждой четверти хода. Все 12 274 HID-отчёта
валидны, ошибок чтения нет. InputPlumber активен, калибровка перед запуском
прошла, текущий экземпляр службы не имеет предупреждений или ошибок.
Пользователь подтвердил плавный ход обоих LT/RT в том же тесте Steam:
аналоговый диапазон проверен на родном устройстве, виртуальном HID и в Steam.
2 октября пользователь проверил LT/RT, крестовину, оба меню и задние кнопки
после каждого из трёх этапов: сон/пробуждение, полное выключение/включение
и смена Game/Desktop/Game Mode. Все этапы прошли. Это пользовательская
проверка управления; журнал службы после холодной загрузки заново не снимался.
Исправление включено в отдельный SD-кандидат с SHA256 `6b228352…`,
описанный выше. Первоначальный файл `77b6f6a6…` сохранён для истории проверки.
На заключительный запрос проверить L4=A и R4=B в игре, обе кнопки громкости,
один встроенный контроллер в Steam и совместную работу с внешним геймпадом
пользователь ответил «Все работает». Приёмка управления на установленной
конфигурации завершена; модель внешнего геймпада и тип подключения не указаны.
Повторная финальная проверка исходников: 37 тестов Linux прошли без пропусков,
журнал — `../preparation/module1/module1-final-tests.log`.
Подробности находятся в локальном
`../preparation/module1/hardware-acceptance.json`.

ABL и внутренняя память Android не перепрошиваются. Возврат к прежней ОС
возможен повторной установкой сохранённого исходного образа; старые игры,
настройки и сохранения таким способом не восстанавливаются. Справочная
[процедура полного backup](RP6-ROADMAP.ru.md#испытания-с-одной-microsd) остаётся
для будущих сценариев, где требуется сохранение данных. В Linux сборочной среде вернуть
сохранённый prebuilt output и rootfs либо подготовить их заново из предыдущей
ревизии. Частичная отмена только YAML не отменяет GPIO-изменения ядра.

Матрица управления для повторения на будущих образах без загрузки пользовательской карты:

- ABXY по маркировке, крестовину в четырёх направлениях и диагонали в игре.
- Стики, нажатия стиков, плечевые кнопки, триггеры и Start/Select.
- Левое меню через Guide, правое через QuickAccess, обе кнопки громкости.
- Независимые назначения L4/R4 в Steam Input и их действия в игре.
- Отсутствие повторных нажатий и второго виртуального встроенного контроллера.
- Внешний USB/BT контроллер вместе со встроенным.
- Повторение после холодной загрузки, сна и переключения Game/Desktop Mode.

TOP-DPAD и Nova аппаратно не проверены. Профили upstream сохранены; скрипт
понимает RP6/TOP-DPAD DTB, но не добавляет GPIO-описания Nova. Другие устройства
SM8550 и SM8650 также не испытаны в этой работе.
